# Проверка полного прохода маршрута согласования от ЦФО «Управление бухгалтерского и налогового учета»

Версия: 04.09.2026  
Тип проверки: ручная сквозная проверка (E2E) с проверкой прав, видимости, возвратов на доработку и истории действий.

## 1. Цель и область проверки

Проверить, что заявка из ЦФО «Управление бухгалтерского и налогового учета» проходит весь маршрут, каждый участник видит только разрешённые ему данные и действия, а возврат на доработку корректно возвращает выбранные строки на непосредственный предыдущий этап.

Проверяются:

- создание и отправка заявки ответственным модуля;
- проверка ответственным ЦФО;
- передача экономисту ЦФО;
- проверка экономистом и заморозка позиции;
- согласование промежуточным согласующим;
- финальная фиксация ЗГД;
- возврат всей позиции и отдельных строк на доработку;
- повторное прохождение изменённых строк;
- видимость заявки, позиции, маршрута, комментариев, уведомлений и истории для каждой роли;
- запрет действий не на своём этапе и повторных действий по уже закрытым строкам.

## 2. Участники и тестовые данные

### 2.1. Участники

| Роль | Тестовый логин текущего стенда | Назначение в проверке |
|---|---|---|
| Администратор | учётная запись администратора | Настройка/контроль маршрута, просмотр всех данных и журналов |
| Ответственный модуля M-1 | `bb_bu_module_resp` | Создание заявки, редактирование и повторная отправка строк |
| Ответственный ЦФО | `bb_bu_1_resp` | Проверка строк ЦФО «Управление бухгалтерского и налогового учета» и передача экономисту |
| Экономист ЦФО | `bb_econ_bu` | Проверка позиции, изменение согласованного факта, возврат на доработку |
| Согласующий | `bb_approver_2` | Промежуточное согласование и возврат экономисту |
| ЗГД | `bb_zgd` | Финальная фиксация и возврат согласующему |

Тест выполняется по текущей ветке ЦФО. Если проверка запускается на другом стенде, искать участников по роли и назначению, а не только по логину.

### 2.2. Маршрут по умолчанию

Направление прохождения:

```text
Ответственный модуля M-1 (bb_bu_module_resp)
        ↓
Ответственный ЦФО (bb_bu_1_resp)
        ↓
Экономист ЦФО (bb_econ_bu)
        ↓
Согласующий (bb_approver_2)
        ↓
ЗГД (bb_zgd)
        ↓
Финальная фиксация
```

### 2.3. Объекты текущей ветки

| Объект | Значение |
|---|---|
| Родительская единица | «ЗЯ» |
| ЦФО | «Управление бухгалтерского и налогового учета» (`09373dca-a541-451f-9641-ac9b2d1aa1f4`) |
| Модуль M-1 | `71da619c-ec50-41fa-9a21-853178ce4772` |
| Модуль M-2 | `7bbbdbef-b898-4cf4-b893-41801e65c162` |
| Шаг ЦФО | `2f20ccd4-e5e7-4bb1-a000-dca412803883` |
| Шаг экономиста | `fc346308-8edd-49f0-ae82-2a4b821bb914` |
| Шаг согласующего | `cd8e0aa3-ac3e-4230-8824-5eb9f642986c` |
| Шаг ЗГД | `b410be4f-e4b7-4f31-b0fd-bf0825787724` |

Важно для текущего стенда: у M-1 назначен `bb_bu_module_resp`, у M-2 активный ответственный не назначен. Для полного прохода заявок обоих модулей сначала назначить ответственного M-2. Иначе проверять только M-1 либо зафиксировать блокирующий дефект настройки доступа.

ID могут отличаться после восстановления другой базы; контрольным признаком остаётся название ЦФО и логины участников.

Создать одну новую заявку текущего бюджетного года с минимум двумя строками:

| Строка | Плановая сумма | Назначение |
|---|---:|---|
| Строка А | 100 | Проверка полного успешного прохода |
| Строка Б | 200 | Частичный возврат и проверка неизменяемой соседней строки |

Для сценария финальной фиксации использовать две строки. Для сценариев возврата желательно выполнять проверку на отдельной заявке, чтобы не смешивать результаты разных веток.

## 3. Что проверять в статусах

| Уровень | Статусы/признаки |
|---|---|
| Заявка | `draft` → `on_review` → `approved` |
| Позиция ЦФО | `on_review`/`waiting` → `on_approval` → `approved` или `on_revision` |
| Строка | `on_review`, `approved`, `approved_with_changes`, `rejected` |
| Заморозка | `frozen = true` после передачи с этапа экономиста дальше |
| Финальная фиксация | `fixed = true` после решения ЗГД; повторное открытие запрещено |

При возврате на доработку проверять одновременно:

- `position.status = on_revision`;
- `current_step_id` равен выбранному непосредственному нижнему шагу;
- выбранные строки снова доступны для действия и имеют `frozen = false`;
- невыбранные строки не стали доступными без причины;
- финально зафиксированные строки не открываются;
- комментарий возврата виден получателю и попал в историю;
- решение по возвращённой строке необходимо принять заново;
- передача дальше недоступна до обработки всех обязательных возвращённых строк.

## 4. Основной сценарий: полный проход без возврата

| № | Кто выполняет | Действие | Ожидаемый результат и что должен видеть участник |
|---:|---|---|---|
| 0 | Администратор | Открыть «Пользователи», «Оргструктура», «Маршрут согласования» и журналы | Видны ЦФО «Управление бухгалтерского и налогового учета», M-1/M-2, назначения, четыре шага и полная история. Порядок маршрута: ЦФО → экономист → согласующий → ЗГД. Администратор видит полную историю, но не должен выполнять бизнес-согласование от имени другого участника. |
| 1 | Ответственный модуля M-1 | Создать заявку, добавить строки А и Б, заполнить статью, сумму, обоснование, аналитику и при необходимости файл | Заявка в `draft`. Видны только доступные пользователю модули и его черновик. Поля заявки и строк редактируемы, доступно удаление строки и отправка. |
| 2 | Ответственный модуля | Нажать «Отправить» | Заявка переходит в `on_review`, строки появляются на проверке ЦФО. В «Маршруте согласования» текущим является этап ответственного ЦФО. Экономист, согласующий и ЗГД ещё не должны иметь доступного действия по этой заявке. |
| 3 | Ответственный ЦФО `bb_bu_1_resp` | По строкам А и Б выбрать решение `approved`; затем завершить проверку ЦФО | Каждая строка имеет принятое решение. До обработки всех строк завершение должно быть недоступно или возвращать ошибку. После завершения заявка остаётся `on_review`, позиция ЦФО подготовлена к передаче. |
| 4 | Ответственный ЦФО `bb_bu_1_resp` | Нажать «Отправить дальше» / «Передать экономисту» | Позиция получает `current_step_id = fc346308-8edd-49f0-ae82-2a4b821bb914`, статус `on_approval`. `bb_econ_bu` получает уведомление. Строки видны, но редактирование ответственным модуля закрыто, если строка не возвращена на доработку. |
| 5 | Экономист ЦФО | Открыть свою позицию и проверить суммы, планы по месяцам, аналитику, обоснования, файлы и комментарии | Видны только позиции назначенных экономисту ЦФО. Доступны решения по незамороженным строкам. Помесячный план экономист не изменяет; он может указать согласованный факт. |
| 6 | Экономист ЦФО | Для строки А выбрать `approved_with_changes`, указать согласованный факт 90 и комментарий; для строки Б выбрать `approved` | Сумма факта строки А равна 90, комментарий сохранён в позиции/истории. Строка Б остаётся без изменения суммы. До принятия решений по обеим строкам завершение проверки недоступно. |
| 7 | Экономист ЦФО `bb_econ_bu` | Нажать «Завершить проверку», затем «Заморозить»/«Отправить дальше» | Позиция передана на шаг `bb_approver_2`, `current_step_id = cd8e0aa3-ac3e-4230-8824-5eb9f642986c`, все строки `frozen = true`, `fixed = false`. Экономист больше не может менять закрытые строки. Согласующий получает уведомление. |
| 8 | Согласующий | Открыть позицию на своём шаге, проверить данные и историю; при необходимости добавить комментарий к позиции | Видны позиция ЦФО, строки, значения плана и согласованного факта, комментарии и маршрут. Доступно согласование и возврат выбранных незакреплённых строк. Редактирование исходных данных строки недоступно. |
| 9 | Согласующий `bb_approver_2` | Нажать «Согласовать» для позиции/всех строк | Позиция передана на шаг ЗГД `bb_zgd`, `current_step_id = b410be4f-e4b7-4f31-b0fd-bf0825787724`, статус `on_approval`. ЗГД получает уведомление. Для промежуточного согласующего доступное действие по этой позиции исчезает. |
| 10 | ЗГД | Открыть позицию и проверить финальные суммы, строки, историю и комментарии | Видны все строки позиции, маршрут до текущего шага, история решений и возвратов. Доступна финальная фиксация незакреплённых замороженных строк. Редактирование сумм и аналитики недоступно. |
| 11 | ЗГД | Зафиксировать сначала только строку А | `fixed` строки А становится `true`, строка Б остаётся `fixed = false`; позиция остаётся на шаге ЗГД. В интерфейсе строка А больше не имеет действий. |
| 12 | ЗГД | Зафиксировать строку Б | `fixed = true` у обеих строк, `current_step_id = null`, позиция `approved`, заявка `approved`. В маршруте все этапы отмечены как завершённые. У всех участников остаётся просмотр результата и истории, но нет действий по окончательно закрытым строкам. |

## 5. Матрица видимости и доступных действий

| Роль | Что видит | Что может сделать | Чего не должен видеть/делать |
|---|---|---|---|
| Администратор | Все заявки, позиции, пользователей, оргструктуру, полный граф маршрута, журналы шагов и историю | Настроить маршрут и назначения, открыть любой объект для контроля | Не должен подменять участника в бизнес-прохождении и финальной фиксации |
| Ответственный модуля | Свои черновики и заявки своего модуля; после отправки — строки своего модуля и связанные данные ЦФО; маршрут с участниками и статусами | Создать/изменить черновик, отправить заявку, принять решение ЦФО, завершить проверку, передать экономисту, исправить только возвращённые модульные строки и отправить их повторно | Не может решать этап экономиста, согласующего или ЗГД; не может менять замороженные/зафиксированные строки |
| Ответственный ЦФО | Заявки модулей своего ЦФО после отправки, позиции своего ЦФО, этап ЦФО и связанные этапы маршрута | Принять/отклонить строки ЦФО, завершить проверку, передать позицию экономисту; повторно обработать строки, возвращённые с этапа экономиста | Не может принять решение за экономиста, согласующего или ЗГД |
| Экономист ЦФО | Заявки и позиции только назначенных ему ЦФО; текущий этап и контекст маршрута; строки, суммы, факт, планы, обоснования, аналитику, файлы, комментарии, историю | Принять строку, выбрать `approved_with_changes`, изменить согласованный факт, завершить проверку, заморозить и передать дальше, вернуть выбранные строки ответственному ЦФО | Не видит черновики чужих модулей; не меняет план по месяцам; не меняет замороженные/зафиксированные строки |
| Согласующий | Позиции своего шага и позиции, которые проходили через него; полный контекст связанного маршрута и история | Согласовать позицию, добавить комментарий, вернуть всю позицию или выбранные незакреплённые строки экономисту | Не может изменять суммы/план/аналитику и не может фиксировать бюджет окончательно |
| ЗГД | Позиции своего финального шага и позиции, которые ранее проходили через его ветку; все строки, статусы, комментарии и историю | Финально зафиксировать одну или несколько незакреплённых строк; вернуть выбранные незакреплённые строки согласующему | Не может открыть уже `fixed` строку; не может редактировать исходные данные |
| Пользователь другой ветки | Ничего из чужой заявки/позиции, кроме явно разрешённого общего справочника | Нет действий по заявке | Проверить ответы `403` на просмотр заявки, позиции и шага |

Для каждой роли дополнительно проверить в интерфейсе:

- показывается только её кнопка действия на текущем этапе;
- у остальных ролей кнопки согласования, передачи и возврата отсутствуют или заблокированы;
- виден статус этапа: «Ожидает согласования», «На согласовании», «На доработке», «Согласовано»;
- в реестре корректно работают флаги `is_current_step_owner`, `is_approval_actionable`, `is_final_approval_actionable`, `is_position_submission_actionable`, `is_revision_actionable`;
- маршрут не подтягивает соседнюю ветку после общего этапа, если она не относится к текущему пользователю/заявке.

## 6. Сценарии возврата на доработку

Во всех сценариях возврата комментарий обязателен. Если не указать целевой шаг, приложение должно выбрать непосредственный нижний шаг автоматически. Явно выбранный `target_step_id` должен быть непосредственным дочерним шагом текущего этапа.

### 6.1. Ответственный ЦФО → ответственный модуля

Выполнять на этапе первичной проверки ЦФО до завершения проверки.

1. Создать и отправить заявку с двумя строками.
2. Для строки А выбрать «На доработку» через реестр статьи/группы ЦФО, указать комментарий «Уточнить расчёт».
3. Проверить, что только строка А имеет признак `is_revision = true` и доступна для редактирования (`is_revision_actionable = true`).
4. Изменить строку А, повторно отправить заявку и принять решение по ней в ЦФО.
5. Проверить, что строка Б не стала доступна для изменения и её исходное решение/данные не сбросились.
6. Завершить проверку ЦФО и передать позицию экономисту.

Ожидаемо: заявка остаётся в `on_review`, в истории появляются `cfo_item_returned_for_revision` и `cfo_items_returned_for_revision`, повторная отправка фиксируется как `request_revision_resubmitted_to_cfo`.

### 6.2. Экономист → ответственный ЦФО

Выполнять после передачи позиции экономисту.

1. Экономист открывает позицию и выбирает строку А.
2. Нажимает «Вернуть на доработку», указывает комментарий и, при необходимости, `suggested_sum_fact = 75`.
3. Ответственный ЦФО видит позицию на `2f20ccd4-e5e7-4bb1-a000-dca412803883`, строка А разморожена и доступна для повторного решения.
4. Строка Б, если она не выбрана в возврате и уже была заморожена, сохраняет `frozen = true` и не становится доступной без возврата.
5. Ответственный ЦФО повторно принимает строку А, завершает проверку и передаёт позицию экономисту.
6. Экономист снова принимает возвращённую строку, завершает проверку, замораживает позицию и отправляет её согласующему.

Ожидаемо: позиция имеет `status = on_revision`, затем возвращается в `on_approval`; старое решение по строке А не засчитывается вместо нового. Комментарий и изменённый согласованный факт видны ответственному ЦФО и в истории.

### 6.3. Согласующий → экономист

Выполнять после того, как экономист заморозил позицию и передал её согласующему.

1. Согласующий выбирает только строку А и указывает комментарий «Проверить сумму».
2. Выполнить возврат на `fc346308-8edd-49f0-ae82-2a4b821bb914`.
3. Проверить, что строка А разморожена и доступна экономисту, а строка Б не открыта повторно.
4. Экономист повторно принимает строку А, завершает проверку и замораживает позицию.
5. Согласующий повторно согласовывает строку А/позицию и передаёт её ЗГД.

Ожидаемо: до повторной обработки строки А передача согласующим дальше невозможна; после обработки текущий шаг снова становится ЗГД.

### 6.4. ЗГД → согласующий

Выполнять после передачи позиции на финальный этап, но до финальной фиксации.

1. ЗГД выбирает одну незакреплённую строку и выполняет возврат на `cd8e0aa3-ac3e-4230-8824-5eb9f642986c` с обязательным комментарием.
2. Согласующий видит выбранную строку как доступную для повторного согласования; невыбранная строка не должна получить новое действие.
3. Согласующий повторно согласовывает выбранную строку.
4. ЗГД снова видит её на финальном этапе и фиксирует.
5. Проверить, что после фиксации заявка не закрывается, пока все строки не имеют `fixed = true`.

Ожидаемо: возврат не снимает фиксацию с уже зафиксированных строк. Попытка открыть такую строку через «reopen-fixed» должна завершиться `409`.

### 6.5. Полная цепочка возврата

Для контрольной проверки истории выполнить последовательность:

```text
ЗГД → согласующий → экономист → ответственный ЦФО → ответственный модуля
```

На каждом переходе возвращать только строку А, оставляя строку Б закрытой. После исправления пройти путь обратно до ЗГД. На каждом шаге проверить:

- получатель видит только свою строку и своё действие;
- отправитель видит статус «На доработке», но не может продолжить до исправления;
- строка Б не размораживается;
- история содержит отдельные события возврата с автором, временем, целевым шагом и комментарием;
- финальная фиксация происходит только после повторного согласования строки А.

## 7. Негативные проверки

| Проверка | Ожидаемый результат |
|---|---|
| Завершить проверку ЦФО с необработанной строкой | `409`, перечислены необработанные строки |
| Завершить проверку экономистом с необработанной строкой | `409`, перечислены необработанные строки |
| Передать экономисту при незавершённой заявке другого модуля того же ЦФО | `409`, передача не выполняется |
| Выполнить действие чужой ролью или по чужому ЦФО | `403` |
| Согласовать позицию не на текущем шаге | `409` |
| Вернуть без комментария | `422` |
| Вернуть на не непосредственный нижний шаг | `422` |
| Выбрать для возврата строку другой позиции | `422` |
| Повторно принять уже согласованную на этом шаге строку | `409` |
| Изменить замороженную строку | `409` |
| Повторно зафиксировать строку ЗГД | `409` |
| Открыть финально зафиксированную строку | `409`, данные не изменились |
| Передать позицию с хотя бы одной неразобранной обязательной строкой | `409` |
| Добавить строку в позицию после её передачи выше ЦФО | `409` |
| Повторно отправить заявку без режима доработки | `409` |

## 9. Итог проверки

Проверка считается пройденной, если:

- все участники видят только свою область данных и свои действия;
- заявка проходит путь от `draft` до `approved` только после последовательного завершения всех этапов;
- экономист передаёт только полностью обработанную и замороженную позицию;
- ЗГД фиксирует строки по отдельности, а заявка закрывается после фиксации последней строки;
- каждый вариант возврата переводит выбранные строки ровно на непосредственный предыдущий этап;
- невыбранные и финально зафиксированные строки не размораживаются;
- после возврата требуется повторное решение по возвращённым строкам;
- комментарии, уведомления и старые/новые значения доступны в истории согласно правам пользователя;
- все негативные проверки возвращают ожидаемый код и не оставляют частичных изменений.
